# FlowerV2

**FlowerV2** 是一个以“种植与照料花朵”为主题的实体互动装置项目。本仓库用于记录装置的**物理结构、传感器与电路设计，以及 ESP32-S3 下位机程序**。上位机使用 **Max（Max/MSP）** 处理交互数据并驱动后续的数字反馈。

> **项目状态：设计与原型开发中。** 本文记录当前设计方向；传感器选型、接线、数据协议和具体实现均可能调整。

## 系统概览

观众通过种下磁性种子、移动磁性水壶、转动风车和操作旋钮与装置互动。传感器采集这些物理动作，ESP32-S3 对信号进行处理，再将交互数据发送给 Max。

**物理动作 → 传感器 → ESP32-S3（采样、滤波、校准与状态识别）→ Max（上位机交互）**

本仓库聚焦硬件与下位机。Max 补丁及视觉、声音等上层表现不属于当前仓库的主要范围。

## 互动部件

| 部件 | 物理交互 | 计划检测方式 | 目标信息 |
| --- | --- | --- | --- |
| 花盆与磁性种子 | 将内置磁铁的种子放入花盆 | 花盆底部的 49E 系列线性霍尔传感器 | **`seed_state`：0/1 开关量**，同时发送连续传感器读数 `seed_value` |
| 磁性水壶 | 将带磁铁的水壶靠近花盆 | 49E 系列线性霍尔传感器 | **`kettle_state`：0/1 开关量**，同时发送连续传感器读数 `kettle_value` |
| 磁编码器风车 | 手动或通过气流带动风车旋转 | 磁体与 49E 系列线性霍尔传感器构成的检测机构 | **`windmill_state`：0/1 转动状态**，以及 `windmill_rpm`；不要求绝对角度 |
| 旋钮 | 转动电位器旋钮 | **电位器 + ESP32-S3 ADC** | 将旋钮位置量化为三个档位 **0、1、2**，不输出连续角度 |

以上均为设计目标，不代表已完成标定或功能验证。

## 硬件方案

### 主控

- **MCU：** ESP32-S3
- **职责：** 传感器采样、信号滤波、基线与阈值校准、交互状态识别，以及向上位机输出数据
- **上位机：** Max（Max/MSP）
- **通信接口及数据格式：** 计划参考 [FlowerV1](https://github.com/YXG001/FlowerV1) 的 USB 串口、空格分隔 ASCII 数字与换行分帧方式；FlowerV2 字段定义尚未最终锁定

### 霍尔传感器

本项目计划使用 **49E 系列的三脚线性模拟霍尔传感器**（供电、接地、模拟输出）。候选标识包括 49E、OH49E、S49E、SS49E，具体型号以实际购入器件为准。其输出是随检测到的磁场变化的模拟电压，而不是简单的开关量。

不同厂家和型号的供电范围、灵敏度、静态输出电压、极性及引脚顺序可能不同，接线前须核对实际器件的数据手册，不假定上述标识完全兼容。

**电气注意事项：** ESP32-S3 的 ADC 引脚不能直接承受 5 V 模拟信号。若使用 5 V 供电的霍尔传感器，必须先确认输出电压范围，并根据需要进行限幅或电平缩放。

### 种子与水壶接近检测（0/1 输出）

花盆底部和水壶检测位置使用 49E 系列线性霍尔传感器采集磁场变化。**交互判断使用二值状态 `seed_state` / `kettle_state`，同时发送对应的连续读数 `seed_value` / `kettle_value`，供 Max 观察和后续调整。** 连续读数暂不解释为物理距离：

| 字段（暂定） | 0 | 1 |
| --- | --- | --- |
| `seed_state` | 未检测到种子接近／有效放置 | 检测到种子接近／有效放置 |
| `kettle_state` | 未检测到水壶接近 | 检测到水壶接近 |

ESP32-S3 内部保留原始 ADC 值及滤波结果，并根据每个传感器的基线和实测阈值生成开关量。`seed_value` 和 `kettle_value` 计划提供连续磁场响应数据（具体采用滤波 ADC 原始数值、相对基线变化还是归一化数值，待固件测试决定）。建议使用带**触发阈值与释放阈值（滞回）**的状态机，防止磁铁在临界位置附近造成 0/1 抖动。

霍尔磁场响应与磁体距离、强度、极性、安装朝向及其他磁体干扰都有关，因此该状态表示**接近检测结果**，而不是某个已知厘米数的绝对距离。多个种子、风车磁体和磁性水壶之间的串扰需要实测。

启动校准应在**种子未放置、水壶未靠近**的已知空闲状态下进行。若在有磁体存在时重新归零，可能把当前磁场错误地当成背景基线。

### 风车磁编码

计划使用霍尔传感器检测风车上磁体经过时的磁场变化。具体磁铁数量、磁极排列和传感器数量尚未确定。

风车侧的目标是识别磁性部件经过传感器时的周期性变化，以估算旋转事件与转速；**不需要绝对角度信息**。`windmill_state` 为二值转动状态（`0` 停止、`1` 正在转动），初步拟根据最近一次有效脉冲及超时时间判断，实际超时与最低可识别转速需要测试。`windmill_rpm` 为估计转速，停止时输出 `0`。磁体布局和所需的霍尔通道数将在原型测试中确定。

### 旋钮：电位器（已选定）

旋钮使用**电位器**，不再采用三个霍尔传感器检测磁性指针的备选方案。电位器两端接合适的供电与 GND，滑动端连接 ESP32-S3 的 ADC 输入；保证滑动端电压不超过 MCU ADC 的允许范围。

ESP32-S3 读取连续 ADC 数值，在固件中转换成三个离散档位，**向 Max 只发送整数 `0`、`1`、`2`**。初始方案可根据实测有效行程将其划分为三段；边界增加适当滞回，防止旋钮停留在两档临界位置时抖动。具体阈值以及是否使用机械定位式电位器，待实际选型后确定。

## 下位机软件（规划）

ESP32-S3 固件预计包含以下功能：

1. 读取各路霍尔传感器和旋钮电位器；
2. 对原始模拟读数进行滤波和校准；
3. 将读数映射为种子、水壶、风车和旋钮的交互状态；
4. 通过与 Max 约定的接口发送数据；
5. 提供用于调试的原始数据输出和标定手段。

沿用 FlowerV1 的「**离散状态在前，连续数据在后**」原则。FlowerV2 将三个开关量及旋钮三档值放在前四项，随后发送种子、水壶的连续传感器读数和风车转速。旋钮读取连续模拟信号，但传输时使用 `knob_value = 0/1/2`。

## 与 FlowerV1 兼容的串口通信方案（草案）

参考 [FlowerV1 的 README](https://github.com/YXG001/FlowerV1/blob/master/README.md) 和 [现有固件](https://github.com/YXG001/FlowerV1/blob/master/src/main.cpp)：

- 连接：ESP32-S3 → USB Serial → Max/MSP
- 波特率：**115200 baud**（沿用 V1）
- 发送周期：**50 ms，约 20 Hz**（沿用 V1）
- 帧格式：**纯 ASCII 数字、空格分隔、换行 `\n` 结束**；正式数据流不夹杂调试说明文字
- 接收端根据字段顺序拆分，避免依赖调试日志或文字标签
- V1 支持接收 `c`/`C` 重新校准；V2 **拟延续该命令**，但需要确保重新归零时磁体已经远离对应传感器

FlowerV1 当前是 `S10 S11 S12 P10 P11 P12`（三路开关 + 三路百分比）；V2 不沿用 Touch 通道编号，而按部件定义字段。

### FlowerV2 建议的数据帧

为方便 Max 按固定顺序解析，初步建议：

```text
seed_state kettle_state windmill_state knob_value seed_value kettle_value windmill_rpm\n
```

示例（**仅为协议草案，不代表已有固件输出**）：

```text
0 0 0 0 0.00 0.00 0.0
1 0 1 1 23.40 0.50 45.2
1 1 1 2 38.10 31.50 120.5
0 1 0 2 0.30 29.20 0.0
```

| 字段 | 类型 | 暂定含义 |
| --- | --- | --- |
| `seed_state` | 整数 `0/1` | 种子未检测到／检测到 |
| `kettle_state` | 整数 `0/1` | 水壶未检测到／检测到 |
| `windmill_state` | 整数 `0/1` | 风车停止／正在转动，依据磁铁经过事件和超时判断 |
| `knob_value` | 整数 `0/1/2` | 电位器位置经 ADC 采样、阈值分档后的三个离散档位 |
| `seed_value` | 浮点数（暂定） | 种子霍尔连续读数；具体量纲与标定方式待定 |
| `kettle_value` | 浮点数（暂定） | 水壶霍尔连续读数；具体量纲与标定方式待定 |
| `windmill_rpm` | 非负浮点数 | 风车估计转速，停止时为 `0`；磁铁数量与脉冲计数方案待验证 |

**七字段的顺序已确定**，具体连续值的量纲、校准方式和数据类型精度仍待测试。示例中的 `seed_value` / `kettle_value` 只是演示数据，不代表已完成传感器标定；不要把它们直接视作距离（厘米）。额外的原始 ADC 调试输出可使用单独调试模式／通道，避免破坏供 Max 解析的七字段帧。
